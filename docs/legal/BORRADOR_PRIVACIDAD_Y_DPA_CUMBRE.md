# Borrador - Privacidad y DPA Cumbre

Estado: borrador interno. Requiere revisión legal antes de publicación o firma.

## 1. Finalidad

Este documento sirve como base para una política de privacidad específica de Cumbre y un acuerdo de tratamiento de datos para clientes B2B.

Cumbre puede procesar datos personales y comerciales para operar módulos de gestión, CRM, POS, catálogo, cobros, facturación, stock, marketing, asistentes e integraciones.

## 2. Roles

Según el caso:

- GEMA/Cumbre puede actuar como responsable de tratamiento respecto de sus propios leads, clientes, usuarios comerciales, facturación, soporte, marketing y analítica.
- El cliente puede actuar como responsable respecto de datos que carga sobre sus propios clientes, proveedores, empleados, usuarios, ventas, cobros, productos, comprobantes y operaciones.
- GEMA/Cumbre puede actuar como encargado/procesador cuando trata datos por cuenta del cliente para prestar el servicio.

## 3. Categorías de datos

Cumbre puede tratar:

- Datos de usuarios: nombre, email, teléfono, rol, permisos, credenciales, actividad.
- Datos de clientes del cliente: nombre, CUIT/DNI si corresponde, email, teléfono, domicilio, historial de compras, cuenta corriente, presupuestos, cobros.
- Datos de proveedores: nombre, CUIT, contacto, listas de precios, condiciones.
- Datos comerciales: productos, servicios, precios, IVA, stock, compras, ventas, caja, comprobantes, presupuestos, oportunidades.
- Datos fiscales/administrativos: comprobantes, puntos de venta, alícuotas, condición fiscal, referencias de pago.
- Datos de soporte: tickets, mensajes, capturas, logs, diagnósticos.
- Datos de uso: accesos, eventos, auditoría, configuración, errores.
- Datos de IA/asistente: consultas, respuestas, recomendaciones y contexto enviado por el usuario.

## 4. Finalidades

Los datos se tratan para:

- prestar el servicio.
- administrar cuentas y usuarios.
- procesar ventas, stock, caja, presupuestos, cobros o facturación.
- brindar soporte.
- mantener seguridad.
- registrar auditoría.
- mejorar producto.
- cumplir obligaciones legales.
- emitir facturación comercial.
- gestionar comunicaciones relacionadas.
- analizar uso y estabilidad.

## 5. Subencargados y proveedores

Pueden intervenir proveedores de:

- hosting/cloud.
- bases de datos.
- backups.
- correo.
- mensajería.
- analítica.
- IA.
- pasarelas de pago.
- soporte.
- monitoreo.
- videollamadas.
- CRM.

Debe mantenerse una lista actualizada de subencargados reales antes de publicar esta política.

## 6. Transferencias internacionales

Si se usan servicios cloud, IA, email, analytics, soporte u otros proveedores alojados fuera de Argentina, puede existir transferencia internacional de datos.

La legislación argentina exige evaluar si el país de destino ofrece nivel adecuado o usar mecanismos de protección como cláusulas contractuales modelo aprobadas por AAIP.

Acción pendiente:

- mapear proveedores reales.
- identificar país de tratamiento.
- revisar contratos/DPA de cada proveedor.
- definir cláusulas aplicables.

## 7. Conservación

Definir por tipo de dato:

- Leads no convertidos.
- Usuarios activos.
- Usuarios dados de baja.
- Datos de clientes del cliente.
- Logs de seguridad.
- Backups.
- Facturación comercial.
- Tickets de soporte.
- Conversaciones de IA.

Regla de producto sugerida:

- No borrar datos automáticamente por superar límites o vencer trial.
- Permitir exportación básica antes de eliminación definitiva.
- Mantener retención técnica razonable para backups, auditoría, cumplimiento y resolución de disputas.

## 8. Derechos de titulares

Se debe habilitar canal para:

- acceso.
- rectificación.
- actualización.
- supresión.
- retiro de consentimiento cuando corresponda.

Cuando GEMA/Cumbre actúe como encargado, debe derivar o asistir al cliente responsable.

## 9. Seguridad

Medidas a documentar:

- autenticación.
- roles/permisos.
- cifrado en tránsito.
- backups.
- segregación lógica de clientes.
- registros de actividad.
- mínimos privilegios.
- monitoreo.
- gestión de incidentes.
- revisión de accesos.

Evitar prometer seguridad absoluta.

## 10. Incidentes

Definir procedimiento:

- detección.
- contención.
- evaluación.
- comunicación interna.
- comunicación a clientes afectados.
- documentación.
- medidas correctivas.

Evaluar obligaciones de notificación según normativa aplicable y contrato.

## 11. IA y datos

La política debe aclarar:

- qué datos puede usar el asistente.
- si se envían datos a proveedores externos de IA.
- si se conservan conversaciones.
- si se usan para mejora del servicio.
- que el usuario no debe cargar datos sensibles innecesarios.
- que recomendaciones de IA deben validarse humanamente en acciones críticas.

## 12. DPA - cláusulas base

Un DPA de Cumbre debería incluir:

- objeto del tratamiento.
- duración.
- naturaleza y finalidad.
- categorías de datos.
- categorías de titulares.
- instrucciones documentadas del cliente.
- confidencialidad.
- medidas de seguridad.
- subencargados.
- asistencia ante derechos de titulares.
- asistencia ante incidentes.
- devolución/eliminación al finalizar.
- auditoría razonable.
- transferencias internacionales.
- responsabilidad y limitaciones.

## 13. Pendientes antes de versión legal

- Definir responsable legal exacto.
- Identificar proveedores reales.
- Confirmar hosting productivo.
- Confirmar si se usará IA externa y cuál.
- Confirmar si se registrarán bases ante AAIP.
- Definir emails de privacidad y soporte.
- Definir períodos de retención.
- Definir proceso de baja/exportación.
- Revisar con abogado especializado en datos personales.
